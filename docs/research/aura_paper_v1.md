# Aura Paper v1 研究契约

状态：冻结候选版
适用范围：AuraBench 1.x / ScenarioSpec 2.x

## 核心命题

Aura 检验的不是“Agent 能否把设备调到目标终态”，而是：

> 静态、最终状态评测会系统性高估智慧家庭 Agent 的可靠性。动态居民、异步设备、部分可观测性与多 Agent 并发进入同一闭环后，任务成功率会下降，并出现最终状态无法揭示的安全、隐私、冲突和陈旧执行问题。

## Episode 最小单位

一个 episode 由以下不可分割的契约组成：

- 冻结的 ScenarioSpec 2.x 与契约 hash；
- static/dynamic 反事实配对身份；
- 初始世界、居民、基础 timeline、目标与 TraceSpec；
- seed、模型、Agent 拓扑、治理策略、观测模型和预算；
- 完整事件轨迹、终态、评价报告与 provenance。

缺少任一项的运行不得进入论文聚合。

## 与 SimuHome 的边界

Aura 不以更多设备、更真实 3D 或单 Agent 工作流调度为主要贡献。Aura 的不可替代差异是：

1. 居民、设备、环境和多个 Agent 在模拟时间中持续相互作用；
2. 每个动态任务都有只改变一个干预因素的静态孪生任务；
3. 成功由终态与完整轨迹共同判定；
4. Agent 拓扑、治理和观测条件可作为受控实验变量。

## 研究问题

- RQ1：同一 Agent 从静态任务进入动态闭环后，成功率下降多少？
- RQ2：多少终态成功运行在中间轨迹中发生过违规？
- RQ3：约束感知的多 Agent 治理能否减少冲突、陈旧动作和违规，同时保持任务成功率？
- RQ4：上述结论在不同模型、拓扑、观测条件和 seed 下是否稳定，代价是多少？

## 第一篇论文明确不做

- 不扩张为真实 Matter/Home Assistant 适配层；
- 不追求数百设备或多户型规模纪录；
- 不使用 LLM 生成 benchmark ground truth；
- 不建设 RL/SFT 训练闭环；
- 不进行人类参与者研究；
- 不把 3D 前端、资产数量或通用平台功能作为核心贡献。

## 主张成立条件

论文中心主张只有在预注册 pilot 与主实验同时满足以下条件时成立：

- 配对样本显示非零且有实际量级的 Static-to-Closed-Loop Gap；
- 存在可复现的 Final-State Blind Spot；
- 至少一种治理机制相对无治理基线显著减少违规，且任务成功率下降不超过 5 个百分点；
- 配对 provenance、工件完整性和确定性重放审计通过；
- 开销、无效运行和未支持假设被完整报告。

若 pilot 在 8–12 对场景、3 个 seed 上无法观察到前三项，停止扩张到 600 episodes，先修改科学问题或运行语义，而不是增加样本掩盖问题。
